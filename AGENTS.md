# AGENTS.md

Протокол для агентов, работающих с репозиторием AiRecruiter. Читается
автоматически в каждой сессии OpenCode. Ростер и права —
[`docs/agents.md`](docs/agents.md), процесс —
[`docs/process.md`](docs/process.md), канон документов —
[`docs/documentation.md`](docs/documentation.md), план этапов —
[`docs/roadmap.md`](docs/roadmap.md), журнал решений —
[`docs/decisions.md`](docs/decisions.md).

## Порядок чтения и preflight

1. `AGENTS.md` — вход, роли, запреты.
2. [`docs/agents.md`](docs/agents.md) — ростер, модели, права, матрица
   скиллов.
3. [`docs/process.md`](docs/process.md) — граф, профили, артефакты.
4. [`docs/roadmap.md`](docs/roadmap.md) — этап, границы, DoD.
5. [`docs/architecture.md`](docs/architecture.md) — текущее состояние кода.
6. [`docs/decisions.md`](docs/decisions.md) и ADR по теме — почему решено
   так.

Перед стартом: `git rev-parse --short HEAD` и `git status --short`. Если HEAD
или состояние дерева не совпадает с ожидаемым — остановиться и сообщить
владельцу. При расхождении `AGENTS.md`, roadmap, decisions и ADR —
остановиться и сообщить владельцу, трактовку не выбирать самостоятельно.

## Роли

Владелец общается только с оркестратором; «владелец» и «заказчик» — одно
лицо. Ростер, модели, уровни, права и матрица скиллов —
[`docs/agents.md`](docs/agents.md); конфиги — `.opencode/agents/*.md`.
Процесс (граф, профили, раунды, handoff через артефакты) —
[`docs/process.md`](docs/process.md).

- orchestrator — делегирует субагентам и проверяет по DoD, файлы не правит.
- planner — декомпозиция этапа, пишет `breakdown.md`.
- coder и coder-deep — код и документы по карточке задачи.
- tester — приёмка, пишет `qa.md`; код и тесты не правит.
- reviewer — ревью diff, пишет `review.md`.
- security — аудит безопасности, пишет `security.md`.
- explore — встроенный read-only поиск.

## Правила процесса

- Работать только в текущем рабочем каталоге; в другие `AiRecruiter-*` не
  переходить. Worktree не используются; условие пересмотра —
  [`docs/roadmap.md`](docs/roadmap.md), «Вне этапов».
- Git-операции (`commit`, `tag`, `push`) по умолчанию выполняет владелец.
  Исключение — явная команда заказчика: тогда операцию выполняет агент.
- Не менять чужой журнал: файл в `docs/work/<этап>/` пишет только его
  роль-владелец; правила артефактов — [`docs/process.md`](docs/process.md).
- Промпт субагента — карточка задачи со строкой `Скиллы:`; отчёт содержит
  строку `Загружены:` с ID скиллов и результатами проверок по ним.
- Не менять существующие тесты без обоснования; новые добавлять.
- Не использовать `!` (null-forgiving), `#pragma`, `NoWarn` ради подавления
  предупреждений.
- Тесты не ходят в сеть и не вызывают GigaChat.
- Статусы вакансий — константы `VacancyStatus`, не строковые литералы; `seen`
  остаётся legacy для старых строк.
- Приёмка перед отчётом: сборка 0/0, тесты, формат, `check-docs.sh`,
  `--parse-samples tests/Fixtures`, `--replay-failed failed_responses`;
  команды и критерии — скилл `dotnet-acceptance`.
- Перед началом каждого этапа оркестратор даёт владельцу полное описание
  предстоящего этапа: что меняется, какие прежние решения устарели, что уже
  реализовано, и вопросы, которые нужно закрыть по контексту. Без этого
  описания этап не начинается.

## Запреты

- В логах и отчётах не выводить содержимое `candidate_summary.md`,
  `resume.txt`, `profile.md`, персональные данные, токены и адрес прокси.
- `candidate_summary.md`, `resume.txt`, `profile.md`, `samples/`,
  `failed_responses/`, `appsettings.json`, `vacancies.db` — локальные файлы,
  в git не попадают; чтение PII-файлов запрещено глобально в
  `.opencode/opencode.jsonc`.
- Не расширять объём этапа: новая работа — через изменение roadmap
  владельцем.
- Субагент не обращается к владельцу напрямую и не меняет модель или
  уровень: смена — только решением владельца.

## Документация

- Документ меняется в том же коммите, что и код. Коммит без нужного
  обновления документа не принимается; «обновлю после коммита» недопустимо.
- Канон: стандарт, реестр фактов (один факт — один владелец), лимиты строк —
  [`docs/documentation.md`](docs/documentation.md). План этапа — roadmap,
  декомпозиция — `docs/work`, объём не меняется.
- Формат ссылок на код: markdown-ссылка с якорем `#L` на строку (например
  `[Program.cs:198-199](src/AiRecruiter/Program.cs#L198-L199)`); голых записей
  вида `путь:строка` в документах нет. При изменении кода перепроверять, что
  строка по ссылке соответствует тексту: `check-docs.sh` проверяет путь и
  якорь, но не содержимое.
- Перед изменением потока или БД — прочитать `docs/architecture.md`.
- Формулировки однозначны: «отложено» — в бэклоге или «Вне этапов» с адресом;
  «отклонено» — не делаем, причина записана. Один термин — одно значение.
- Термины решений:
  - `сделано` — код и документы уже в репозитории;
  - `план` — в `docs/roadmap.md`, есть этап и границы;
  - `отложено` — в бэклоге или «Вне этапов», нужен отдельный запуск;
  - `не входит в этап` — граница текущего этапа, не отказ от работы;
  - `отклонено` — не делаем; причина записана.
- Чеклист перед коммитом:
  1. Код и `docs/architecture.md` согласованы.
  2. Запись в `CHANGELOG.md` в `[Unreleased]`.
  3. Новое архитектурное решение — новый ADR в `docs/adr/`; процессное —
     запись в `docs/decisions.md`.
  4. Статус и критерии этапа в `docs/roadmap.md` обновлены.
  5. `README.md` обновлён при изменении запуска или конфигурации.
  6. `bash scripts/check-docs.sh` — без предупреждений.
  7. Сборка, тесты, формат — без ошибок.
  8. В документах текущего состояния (README, architecture) решение не
     описано как текущее поведение: у нереализованного есть пометка «план,
     шаг N» или «в коде пока нет», у реализованного — ссылка на код.

## Скиллы

- Проектные скиллы OpenCode лежат в `.opencode/skills/`; это рабочие
  чек-листы, а не источник правды и не расширение границ этапа. При
  расхождении приоритет у `AGENTS.md` и `docs/roadmap.md`, расхождение
  сообщается владельцу.
- Скилл загружается инструментом `skill` по точному ID — имени папки, а не
  по `name` из frontmatter; принудительная загрузка — `@` и ID.
- Матрица скиллов роли — [`docs/agents.md`](docs/agents.md). Роль загружает
  только скиллы своей матрицы; лишний скилл не загружается, расхождение с
  промптом сообщается владельцу до начала работы.
- MCP: только `context7` в `.opencode/opencode.jsonc` — документация
  библиотек. Через него не передаются код, резюме, сводка кандидата,
  переписка и персональные данные.

## Этапы

Порядок: **3.1 → 3.2a → 3.2 → 3.3 → 3.4 → 3.5 → 3.6**. План, границы,
критерии готовности, зависимости и риски — в
[`docs/roadmap.md`](docs/roadmap.md); там же трек «Процесс агентов». Здесь
этапы не дублируются.
