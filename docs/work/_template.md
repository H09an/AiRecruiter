# Шаблон артефактов этапа

Структура журнала исполнения `docs/work/<этап>/`. Каталог создаётся лениво:
файл появляется при первой записи роли-писателя. Правила —
[`docs/process.md`](../process.md), раздел «Артефакты (blackboard)».

Общая шапка каждого файла: ID задачи, вердикт (PASS / FAIL / BLOCKED),
blocking, next. Ответ роли оркестратору — не больше 10 строк с путём к
файлу; полный текст — только в артефакте.

## `docs/work/<этап>/breakdown.md` — planner

- задачи: ID `этап-E-S-T`, цель, границы, роль, сложность, профиль,
  зависимости, скиллы, приёмка, документы к обновлению;
- трассировка «пункт DoD roadmap → задачи»;
- история перепланирования (append-only): дата, причина, изменения, ID.

## `docs/work/<этап>/coder.md` — coder / coder-deep

- изменённые файлы и суть правок; что перенесено, что изменено по смыслу;
- тесты и сборка: команды, фактические результаты;
- строка «Загружены:» с ID скиллов и результатами проверок по ним;
- риски и что осталось.

## `docs/work/<этап>/qa.md` — tester

- PASS/FAIL по каждой команде приёмки с фактическим результатом;
- «не проверено» с причиной вместо догадки;
- баг-репорты: задача, шаг, ожидание, факт, улика, минимальный фикс.

## `docs/work/<этап>/review.md` — reviewer

- findings: blocking / should-fix / nit;
- место — markdown-ссылка на код с якорем `#L`; минимальный фикс;
- проверка границ этапа и документов.

## `docs/work/<этап>/security.md` — security

- findings: critical / high / medium / low;
- сценарий, последствие, минимальный фикс;
- улика — имя файла, строка и тип данных; значения PII и токенов не
  выводятся.
