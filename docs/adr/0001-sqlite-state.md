# 0001. Состояние вакансий в SQLite вместо seen_vacancies.txt

## Статус

Принято.

## Дата

2026-11-17 (коммит
[67a4baa](https://github.com/H09an/AiRecruiter/commit/67a4baa)).

## Контекст

Первоначально список просмотренных вакансий вёлся в файле `seen_vacancies.txt`.
Для калибровки порога нужны статусы вакансий, дедуп по работодателю и
распределение оценок — плоский файл этого не даёт. Решение записано в
[docs/decisions.md, раздел «Журнал решений»](../decisions.md#журнал-решений).

## Решение

Состояние вакансий хранится в SQLite (`Microsoft.Data.Sqlite` + Dapper) в файле
`vacancies.db`.

Факты в коде:

- создание таблицы `vacancies`, удаление `meta`, миграция колонок и перевод
  legacy-записей в `analysis_failed` в одной транзакции —
  [VacancyRepository.cs:57-152](../../src/AiRecruiter/Storage/VacancyRepository.cs#L57-L152);
- инициализация хранилища —
  [Program.cs:198-199](../../src/AiRecruiter/Program.cs#L198-L199).

## Последствия

Для кода:

- один источник правды — БД; статусы, дедуп и калибровочная статистика берутся
  из неё;
- все оценки, включая низкие, пишутся в БД — без них нельзя калибровать порог.

Что ещё не сделано:

- колонки `experience` / `employment` / `work_format` / `published_at` и
  заполнение `employer_id` добавляются в 3.2a.

Обновлено: meta и миграция удалены в 3.2a (коммит 3).
