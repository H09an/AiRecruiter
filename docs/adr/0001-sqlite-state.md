# 0001. Состояние вакансий в SQLite вместо seen_vacancies.txt

## Статус

Принято.

## Дата

2026-11-17 (коммит [67a4baa](https://github.com/H09an/AiRecruiter/commit/67a4baa)).

## Контекст

Первоначально список просмотренных вакансий вёлся в файле `seen_vacancies.txt`. Для калибровки порога нужны статусы вакансий, дедуп по работодателю и распределение оценок — плоский файл этого не даёт. Решение записано в [AGENTS.md, раздел «Журнал решений»](../../AGENTS.md#журнал-решений).

## Решение

Состояние вакансий хранится в SQLite (`Microsoft.Data.Sqlite` + Dapper) в файле `vacancies.db`.

Факты в коде:

- создание таблиц `vacancies` и `meta`, миграция колонок, перевод legacy-записей в `analysis_failed` — [VacancyRepository.cs:46-104](../../src/AiRecruiter/Storage/VacancyRepository.cs#L46-L104);
- инициализация хранилища и однократная миграция из `seen_vacancies.txt` со статусом `seen` — [Program.cs:191-220](../../src/AiRecruiter/Program.cs#L191-L220).

## Последствия

Для кода:

- один источник правды — БД; статусы, дедуп и калибровочная статистика берутся из неё;
- все оценки, включая низкие, пишутся в БД — без них нельзя калибровать порог.

Что ещё не сделано:

- миграция из `seen_vacancies.txt` всё ещё выполняется при каждом старте — [Program.cs:194-220](../../src/AiRecruiter/Program.cs#L194-L220); её удаление запланировано на 3.2a;
- таблица `meta` создаётся, но не используется;
- колонки `experience` / `employment` / `work_format` / `published_at` и заполнение `employer_id` добавляются в 3.2a.
