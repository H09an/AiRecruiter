# 0010. План этапов в отдельном документе

## Статус

Принято.

## Дата

2026-11-20.

## Контекст

План этапов 3.1–3.6 жил в [AGENTS.md](../../AGENTS.md). В нём были только
название и краткое содержание этапа. Не было границ «входит / не входит»,
критериев готовности, зависимостей, статусов, рисков, документов и тестов этапа.

Порядок в списке (`3.2` → `3.2a`) противоречил тексту: 3.2a должен идти до
калибровки. Чтобы понять, что делать дальше, приходилось читать `AGENTS.md`,
[`docs/architecture.md`](../architecture.md), [`CHANGELOG.md`](../../CHANGELOG.md) и ADR.

`AGENTS.md` — процессная рамка: роли и правила. Журнал решений — отдельный
документ. План — другой жанр с другим жизненным циклом: у него есть статусы,
зависимости и приёмка.

## Рассмотренные варианты

1. Оставить план в `AGENTS.md` и дополнить критериями готовности. Отклонено:
   файл смешивает процесс и план, растёт, статусы этапов конкурируют с
   правилами.
2. Вести план только в GitHub Issues/Projects. Отклонено: план не версионируется
   вместе с кодом и не читается агентами без доступа к трекеру.
3. Отдельный [`docs/roadmap.md`](../roadmap.md). Принято.

## Решение

- `docs/roadmap.md` — единственный источник плана: цель, границы, зависимости,
  критерии готовности, статус, риски, документы и тесты этапа.
- `AGENTS.md` хранит процесс, [`docs/decisions.md`](../decisions.md) — журнал решений; раздел «Этапы» содержит только порядок и ссылку на roadmap.
- Порядок этапов: **3.1 → 3.2a → 3.2 → 3.3 → 3.4 → 3.5 → 3.6**.
- Статусы: `planned`, `in progress`, `blocked`, `done`, `dropped`.
- Roadmap ссылается на ADR, `docs/architecture.md` и `CHANGELOG.md`, а не
  дублирует их.
- Задачи уровня кода остаются в чек-листах этапа или Issues.

## Последствия

Для документации:

- появился один источник ответа «что дальше и что считается готовым»;
- `AGENTS.md` стал короче и вернулся к роли процессной рамки;
- статус этапа нужно обновлять в том же коммите, что и работу;
- `scripts/check-docs.sh` пока не проверяет статусы roadmap; это возможное
  расширение.

Риски:

- roadmap может устареть, если статус не обновлять. Мера: пункт в чек-листе
  `AGENTS.md` и правило «`done` только по DoD».
- roadmap может превратиться в дубль `CHANGELOG.md`. Мера: завершённые этапы
  сжимаются до строки в сводке, подробности остаются в `CHANGELOG.md`.
