# 0012. Полное описание вакансии в user-сообщении

## Статус

Принято.

## Дата

2026-11-24 (этап 3.2a, шаг 5).

## Контекст

Прежде user-сообщение строилось по правилу «есть `ТРЕБОВАНИЯ` — секции, иначе
`ПОЛНОЕ ОПИСАНИЕ`»: вакансии с длинным описанием и пустым блоком требований
теряли текст, а вакансии с описанием длиннее лимита обрезались молча.
Решение записано в [docs/decisions.md, раздел «Данные и журнал»](../decisions.md#данные-и-журнал-этап-32a).

## Решение

Правило блоков user-сообщения:

- `Description` не пуст и длина ≤ 6000 — один блок `ПОЛНОЕ ОПИСАНИЕ`;
  `СТЕК ПРОЕКТА`, `ОБЯЗАННОСТИ`, `УСЛОВИЯ` не добавляются;
- `Description` не пуст и длина > 6000 и есть непустые секции — блоки
  `ТРЕБОВАНИЯ` (если непуст), непустые `ОБЯЗАННОСТИ`/`УСЛОВИЯ` и непустой
  `СТЕК ПРОЕКТА`; факт отката и длина `Description` пишутся в лог;
- `Description` не пуст, длина > 6000 и секций нет — блок `ПОЛНОЕ ОПИСАНИЕ`
  с первыми 6000 символами; в лог пишется откат с длиной исходного описания и
  пометкой «отправлено 6000»;
- описание пусто (маркер `Описание не загружено` описанием не считается), но
  секции непусты — сборка из секций; непустой `СТЕК ПРОЕКТА` добавляется к ним;
- нет ни описания, ни секций — GigaChat не вызывается, вакансия получает
  `analysis_failed`.

Блоки `ВАКАНСИЯ`, `НАВЫКИ` и метаданные страницы добавляются всегда.

  [JobAnalyzer.cs:214-227](../../src/AiRecruiter/Analyzers/JobAnalyzer.cs#L214-L227);
- сборка блоков —

## Последствия

Для кода:

- длинное описание без секций попадает в промпт только первыми 6000
  символами — остаток в промпт не попадает;
- полное описание сохраняется в колонку `description` только для
  `analysis_failed` / `analysis_abandoned` и вызовов с повтором; при успехе
  очищается — колонка не архив;
- число токенов запроса растёт для длинных описаний; критерий пересмотра
  `MaxTokens` — [ADR-0004](0004-max-tokens-1200.md).

Что ещё не сделано:

- отдельные блоки промпта по колонкам (`main_text`, `key_skills` и др.) и
  ретенция `llm_calls` — после калибровки;
- `main_text_source` — поле журнала `llm_calls`, шаг 7.
