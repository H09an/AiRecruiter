# ADR-0013: Сетевые ошибки останавливают прогон

## Статус

Принято

## Дата

2026-11-24

## Контекст

Анализ вакансии вызывает GigaChat по HTTPS. Сетевые сбои (обрыв соединения,
таймаут HTTP, недоступность API) и отказ авторизации (`401`) раньше попадали в
общий `catch (Exception)` в цикле `Program`: строка оставалась `new` без
`fail_reason`, попытка не фиксировалась, вакансия молча переанализировалась при
каждом появлении в выдаче. Без записи причины и без лимита попыток
`analysis_abandoned` (шаг 6 этапа 3.2a) невозможно: лимит без причин нельзя
разобрать вручную, а бесконечные повторы тратят токены.

Решение владельца (шаг 6): ошибки анализа не делятся по типу, кроме сетевых —
неразобранный JSON, отсутствие описания и секций, исключение в анализе — одна
категория `analysis_failed`, каждый случай даёт `attempts + 1` и причину в
`fail_reason` (не длиннее 500 символов). Сетевые ошибки и `401` останавливают
прогон: строки остаются `new`, `attempts` не меняется.

## Решение

1. Сетевая категория определена `JobAnalyzer.IsRunStoppingException`:
   `HttpRequestException` (включая `401` и `429`/`5xx` после внутренних
   повторов `CallGigaChatAsync`) и `TaskCanceledException` по таймауту HTTP.
   `OperationCanceledException` без таймаута (отмена процесса) и остальные
   исключения — не остановка прогона.
2. В `Program` порядок catch: сетевая остановка → лог, пометка остановки,
   `break` из цикла (без `return` из `Main`); `OperationCanceledException` —
   проброс; остальные исключения → `SaveAnalysis` со статусом
   `analysis_failed`, `fail_reason` из сообщения исключения, `attempts + 1`.
3. Внешний цикл `for attempt < 3` в `AnalyzeVacancyAsync` удалён: один вызов
   анализа, затем repair. Лимит попыток ведёт `attempts` в БД.
4. Внутренние повторы `CallGigaChatAsync` (`401`, `429`/`5xx`, таймаут)
   сохраняются; их исчерпание — остановка прогона.

## Последствия

- Сетевые ошибки не списывают попытки: после восстановления сети прогон берёт
  вакансию заново со счётчиком 0.
- Устойчивые не-сетевые ошибки достигают `attempts >= 3` и переводятся в
  `analysis_abandoned` (sweep или `SaveAnalysis`), вакансия прекращает
  потреблять токены до ручного сброса.
- Причина каждого сбоя записана в `fail_reason`, разбор — по ней,
  `description` и `failed_responses/`.
- `[ИТОГ]` продолжает формироваться и после остановки; завершение `Program`
  и будущие режимы 3.4 не ломаются.
