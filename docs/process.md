# Процесс агентов

Процесс v2: оркестратор и субагенты, handoff через артефакты. Ростер,
модели и права — [`docs/agents.md`](agents.md); вход и запреты —
[`AGENTS.md`](../AGENTS.md); план этапов — [`docs/roadmap.md`](roadmap.md).

## Граф

```text
владелец → orchestrator → planner → orchestrator → coder / coder-deep
         → tester → reviewer → security → orchestrator → владелец
```

- Оркестратор делегирует и проверяет по DoD; файлы не правит.
- `explore` вызывается оркестратором по необходимости (read-only поиск).
- Состав цепочки зависит от профиля задачи; reviewer и security пока
  запускаются последовательно, параллельность — шаг P3 трека «Процесс
  агентов» в roadmap.
- Git `commit`, `tag`, `push` выполняет владелец; оркестратор готовит
  точные команды и текст сообщения.

## Чекпойнт владельца

Владелец общается только с оркестратором. Обязательные чекпойнты:

1. До старта этапа: описание этапа и `breakdown.md` согласованы.
2. Перед `commit`, `tag`, `push`: владелец выполняет операцию сам либо
   даёт явную команду агенту.
3. Эскалация: исчерпаны раунды или перепланирования, недоступна модель,
   расхождение документов, вопрос вне границ задачи.

Без решения владельца на чекпойнте процесс не продолжается.

## Профили

| Профиль | Цепочка | Когда |
|---|---|---|
| trivial | coder → tester | одна локальная правка без схемы, промпта и PII |
| standard | planner → coder → tester → reviewer | обычная задача этапа |
| risky | planner → coder-deep → tester → reviewer → security | схема БД, промпт, PII, внешние API |
| этап | полный граф с чекпойнтами и трассировкой DoD | коммит этапа целиком |

Профиль назначает планировщик в карточке; оркестратор может повысить
профиль, но не понизить без решения владельца.

## Раунды, бюджет, эскалация

- Раунд доработки: замечания tester/reviewer/security возвращаются кодеру
  (ошибка кода) или планировщику (ошибка планирования). Не больше 3 раундов
  на задачу и 2 перепланирований этапа; дальше — чекпойнт владельца.
- Один повтор субагента на задачу (сбой запуска, обрыв); второй провал —
  эскалация владельцу.
- Бюджет шагов роли — поле `steps` в её конфиге; при исчерпании шагов
  субагент отдаёт краткий итог, оркестратор решает повтор или эскалацию.
- Недоступная модель — остановка и сообщение владельцу; молчаливая замена
  запрещена (fallback — [`docs/agents.md`](agents.md)).

## Трассировка

Пункт DoD roadmap → задачи `breakdown.md` (ID `этап-E-S-T`) → артефакты
ролей. Оркестратор проверяет: каждый пункт DoD закрыт ссылкой на артефакт,
задач вне границ roadmap нет. Формат декомпозиции — скилл
`task-decomposition`.

## Цикл вопросов

Субагент → оркестратор → владелец → оркестратор → субагент. У субагентов
`question` запрещён; напрямую к владельцу они не обращаются. Ответ
владельца передаётся адресату без пересказа переписки другим ролям.

## Карточка задачи

Промпт субагента — карточка, не пересказ отчётов. Поля:

- ID задачи (`этап-E-S-T`) и роль-адресат;
- профиль и сложность;
- цель и границы (что не входит);
- путь к артефакту роли и пути к артефактам-входам;
- строка `Скиллы:` (только матрица роли);
- приёмка: команды и критерии PASS;
- blocking: что мешает, если есть.

## Матрица чтения

| Роль | Читает |
|---|---|
| orchestrator | все артефакты этапа диапазоном, roadmap, конфиги ролей |
| planner | roadmap (этап, DoD), architecture, decisions, ADR по теме |
| coder, coder-deep | карточку, `breakdown.md`, architecture, скиллы по области |
| tester | карточку, `breakdown.md`, `coder.md`, DoD roadmap |
| reviewer | diff, `coder.md`, `qa.md`, roadmap (границы) |
| security | diff, конфиги, `coder.md`, модель угроз скилла |

Чужой журнал не правится никогда; чтение — по матрице, не «всё подряд».

## Артефакты (blackboard)

- Паттерн: общая доска `docs/work/<этап>/`, роли общаются через файлы, не
  пересказом переписки. Handoff — путь к артефакту в карточке и отчёте.
- Каталог этапа создаётся лениво: файл появляется при первой записи роли;
  пустых каталогов и заготовек в git нет. Шаблон структуры —
  [`docs/work/_template.md`](work/_template.md).
- Один писатель на файл: `breakdown.md` — planner; `coder.md` — coder /
  coder-deep; `qa.md` — tester; `review.md` — reviewer; `security.md` —
  security. Оркестратор не пишет ничего.
- Артефакт читается диапазоном строк (шапка и вердикт, затем разделы);
  логи и цитаты отчётов в промпты не вставляются.
- Отчёт субагента оркестратору — не больше 10 строк: ID, вердикт, путь к
  артефакту, blocking, next; полный текст — только в файле.
- Изоляция: один писатель в каталоге; read-only роли без worktree;
  worktree отложен, условие — в [`docs/roadmap.md`](roadmap.md), «Вне
  этапов».

## Повтор и эскалация

- Повтор субагента — один раз, с той же карточкой; изменение карточки —
  новый раунд, а не повтор.
- Эскалация владельцу: 3 раунда или 2 перепланирования исчерпаны, модель
  недоступна, документы расходятся, требуется работа вне границ roadmap.
- Решение владельца фиксируется в `docs/decisions.md` или ADR; устные
  договорённости процесс не меняют.
