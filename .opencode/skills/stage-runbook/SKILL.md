# Runbook этапа AiRecruiter

Использовать перед началом этапа и при его закрытии. Скилл задаёт порядок,
`AGENTS.md` и `docs/roadmap.md` остаются источником правил и объёма.

## 1. Preflight

```sh
git rev-parse --short HEAD
git status --short
```

Сверить с ожидаемым состоянием. При расхождении — остановиться и сообщить.

Прочитать:

- `AGENTS.md` — роли, правила, журнал решений;
- `docs/roadmap.md` — этап, границы, DoD, порядок работ;
- `docs/architecture.md` — текущий поток и схема;
- ADR по теме.

## 2. Описание этапа

До начала работ дать владельцу:

- что меняется;
- какие прежние решения устарели;
- что уже реализовано;
- какие вопросы нужно закрыть по контексту.

Без этого этап не начинать.

## 3. Передача работы

Канал — по `AGENTS.md`: только через владельца; субагент — по его разрешению.

- Координатор: задача на этап или возврат Архитектору с обязательными скиллами.
- Архитектор: промпт с шапкой `Роль:`, границами, запретами, приёмкой и строкой
  `Скиллы:` (только нужные по ситуации скиллы с пояснением); модель в промпте не
  фиксируется — она указана в таблице ролей, менять её может только владелец.
- Кодер: реализация в своём worktree, отчёт с файлами, тестами, сборкой,
  рисками, обновлёнными документами и строкой `Загружены:`.
- Координатор: проверка, приёмка или возврат на доработку; сверяет `Скиллы:` и
  `Загружены:`.

Git — по `git-workflow`: по умолчанию выполняет владелец, исключение —
явная команда заказчика. Координатор готовит точные команды и сообщение.

## 4. Приёмка

Использовать скилл `dotnet-acceptance`.

Дополнительно проверить:

- `docs/architecture.md` соответствует коду;
- `CHANGELOG.md` содержит запись в `[Unreleased]`;
- `docs/roadmap.md` — статус и критерии этапа;
- `README.md` — если менялись запуск или конфигурация;
- ADR — если принято новое решение;
- `bash scripts/check-docs.sh` — без предупреждений;
- качество текста документов — `docs-quality`.

## 5. Закрытие и тег

- `done` — только после закрытия всех пунктов DoD, записи в `CHANGELOG.md` и
  тега.
- Промежуточный тег с суффиксом `-planning` не переводит этап в `done`.
- Механика тегов, push и запрет force-push — `git-workflow`; правила вех —
  `docs/roadmap.md`, раздел «Вехи и теги».

## 6. Отчёт

Указать:

- что изменено и почему;
- затронутые файлы;
- добавленные тесты;
- результаты приёмки;
- что осталось и где записано (roadmap, бэклог, ADR).
