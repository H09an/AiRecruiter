# Декомпозиция задач AiRecruiter

Чек-лист планировщика. Полный результат — `docs/work/<этап>/breakdown.md`;
ответ оркестратору — не больше 10 строк: ID, вердикт, путь, blocking, next.
Пересказ файла в ответе запрещён.

## Эпик → стори → задача

- Эпик — шаг этапа из `docs/roadmap.md`; стори — проверяемый кусок эпика;
  задача — работа одной роли за один запуск.
- ID задачи: `этап-E-S-T`, например `3.2a-7-1-2` (этап 3.2a, эпик 7,
  стори 1, задача 2). ID не переиспользуются.
- Поля задачи: ID, цель, границы (что не входит), роль, сложность, профиль,
  зависимости, пути артефактов, скиллы, приёмка, документы к обновлению.
- Сложность: trivial (одна правка), standard (обычная задача), risky
  (схема БД, промпт, PII, внешние API); профиль цепочки по сложности —
  `docs/process.md`.

## Трассировка и объём

- Каждый пункт DoD этапа покрыт хотя бы одной задачей; таблица
  «пункт DoD roadmap → задачи» обязательна в `breakdown.md`.
- Задач без пункта DoD или границы roadmap нет; расширять объём запрещено:
  новая работа — через изменение roadmap владельцем.
- Требования к документам: задача перечисляет документы, которые меняются
  в том же коммите (канон — `docs/documentation.md`).

## Перепланирование

- История перепланирования — append-only раздел `breakdown.md`: дата,
  причина, что изменилось, какие ID затронуты; старые записи не удаляются.
- Лимит перепланирований и эскалация — `docs/process.md`.
- Вопросы — оркестратору; объём и границы не трактуются самостоятельно.

## Инкрементальная запись

- `breakdown.md` пишется инкрементально: каркас (шапка, эпики,
  трассировка DoD) — первым делом, детали задач сохраняются по мере
  готовности, не в конце запуска.
- При возобновлении после обрыва читать свой файл, а не перечитывать
  источники заново; дорисовывать недостающие разделы поверх каркаса.
